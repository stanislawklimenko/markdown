# Proof-of-Concept (PoC)

> **Цель PoC** — подтвердить, что архитектурные решения работают на реальных (или приближенных к реальным) данных.  
> Мы реализовали два сквозных сценария:  
> - **Happy Path** – полная автоматизация обработки тикета;  
> - **Fallback Path** – эскалация при низкой уверенности или недоступности LLM.  
> Код не является production‑готовым, но демонстрирует все ключевые шаги пайплайна.

---

## 1. Структура PoC

```text
poc/
├── orchestrator.py          # Основной оркестратор (последовательный вызов модулей)
├── classifier.py            # Классификация интента и извлечение сущностей (лёгкая модель)
├── pii_anonymizer.py        # Удаление PII (регулярки + NER)
├── rag_retriever.py         # Поиск по базе знаний (BM25 + векторы)
├── llm_generator.py         # Генерация ответа через OpenAI API (или мок)
├── confidence_gate.py       # Шлюз уверенности (сравнение эмбеддингов)
├── fallback_handler.py      # Обработка fallback-сценариев (эскалация, шаблоны)
├── data/
│   ├── sample_tickets.json  # 10 тестовых тикетов (разных интентов)
│   └── knowledge_base.json  # Статьи базы знаний (20 шт.)
└── output/                  # Результаты работы (логи, сгенерированные ответы)
