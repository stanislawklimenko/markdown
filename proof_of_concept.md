# Proof-of-Concept (PoC)

> Цель PoC — подтвердить, что архитектурные решения работают на реальных (или приближенных к реальным) данных. Мы реализовали два сквозных сценария: **happy path** (полная автоматизация) и **fallback path** (эскалация при низкой уверенности или недоступности LLM). Код не является production‑готовым, но демонстрирует все ключевые шаги пайплайна.

---

## 1. Структура PoC

```text
poc/
├── orchestrator.py          # Основной оркестратор (последовательный вызов модулей)
├── classifier.py            # Классификация интента и извлечение сущностей (легкая модель)
├── pii_anonymizer.py        # Удаление PII (регулярки + NER)
├── rag_retriever.py         # Поиск по базе знаний (BM25 + векторы)
├── llm_generator.py         # Генерация ответа через OpenAI API (или мок)
├── confidence_gate.py       # Шлюз уверенности (сравнение эмбеддингов)
├── fallback_handler.py      # Обработка fallback-сценариев (эскалация, шаблоны)
├── data/
│   ├── sample_tickets.json  # 10 тестовых тикетов (разных интентов)
│   └── knowledge_base.json  # Статьи базы знаний (20 шт.)
└── output/                  # Результаты работы (логи, сгенерированные ответы)

---

## 2. Happy Path (полная автоматизация)

### Сценарий
> Пользователь пишет в чат:  
> *«Не могу войти в аккаунт, забыл пароль. Мой email: user@example.com»*

### Ожидаемый результат
1. **PII анонимизирован** – email заменён на `[EMAIL]`.  
2. **Классификация** – интент определён как **`PASSWORD_RESET`**, извлечена сущность `email`.  
3. **RAG-поиск** – найдена статья *«Как сбросить пароль»* и похожий решённый тикет.  
4. **Генерация ответа** – LLM создаёт вежливую инструкцию по сбросу пароля.  
5. **Шлюз уверенности** – выдаёт значение **0,95** (высокая уверенность).  
6. **Финал** – ответ отправляется пользователю, тикет автоматически закрывается.

## 3. Fallback / Risky Path

### Сценарий
> Пользователь пишет:  
> *«Мне пришёл неправильный счёт за прошлый месяц. Номер заказа #12345. Я требую перерасчёта!»*

### Особенности
- Интент **`BILLING_DISPUTE`** – относится к высокорисковым (финансы).  
- В базе знаний нет точной статьи по перерасчёту (RAG возвращает общую информацию).  
- LLM генерирует ответ, но шлюз уверенности находит расхождение (галлюцинация: сумма не совпадает с данными биллинга).  
- Уверенность **0,68** (ниже порога).  
- Система **эскалирует тикет агенту**, но в интерфейс агента подгружает найденные документы в качестве подсказки.
